# ТЕХНІЧНЕ ЗАВДАННЯ ТА ПЛАН РЕАЛІЗАЦІЇ

## Проєкт: Binance Anomaly Radar, Local Database & Real-Time Scoring Screener

### 1. Загальний опис та мета системи

Створення високопродуктивного автономного комплексу для моніторингу, реєстрації та ранжування криптовалютних аномалій на біржі Binance у режимі реального часу.

Сервіс вирішує такі задачі:

1. Безперервний збір даних по всіх парах до USDT через асинхронні WebSockets.
2. Первинна фільтрація потоку та збереження всіх зафіксованих аномалій у локальну базу даних SQLite.
3. Онлайн-розрахунок мультифакторного рейтингу монет (Score) за 5 ключовими параметрами.
4. Відображення динамічного рейтингу монет у веб-інтерфейсі без затримок із можливістю глибокого аудиту окремого активу (стакан, стрічка угод, історія сплесків).

---

### 2. Стек технологій та системні вимоги

* **Бекенд:** Python 3.11+ (`asyncio`, `websockets`, `httpx`).
* **База даних:** SQLite3 (асинхронна бібліотека `aiosqlite`) із конфігурацією швидкого запису `PRAGMA journal_mode = WAL;`.
* **Фронтенд:** Single Page Application (`index.html`, `app.js`) без важких фреймворків; Tailwind CSS (CDN); прямі з'єднання через нативний WebSocket API.

---

### 3. Математична модель відбору та ранжування (Scoring Model)

#### 3.1. Обов'язкові фільтри відсікання (Hard Filters)

Монета потрапляє в аналітичну обробку, лідерборд та реєструється в базі даних тільки за одночасного виконання двох умов:

1. **Сплеск об'єму ($\Delta V$):** перевищення ковзного середнього базового періоду на $\ge 150\%$.
2. **Волатильність ($\sigma$):** амплітуда коливання ціни за розрахункове вікно $\ge 10\%$:
   $$\sigma = \frac{Price_{max} - Price_{min}}{Price_{min}} \times 100\% \ge 10\%$$

#### 3.2. Метрики та розрахунок компонентів оцінки

1. $S_{vol}$ **(Об'єм):** Нормалізований показник приросту об'єму (чим більше $>150\%$, тим вищий бал).
2. $S_{vola}$ **(Волатильність):** Нормалізований показник цінового діапазону (чим більше $>10\%$, тим вищий бал).
3. $S_{trades}$ **(Кількість угод):** Інтенсивність потоку угод у стрічці (Trades/Min).
4. $S_{depth}$ **(Щільність стакана):** Сумарний об'єм лімітних заявок (Bids + Asks) у діапазоні $\pm 1\%$ від поточної ціни.
5. $S_{price}$ **(Ціновий коефіцієнт):** Пріоритизація монет вартістю до $2\text{ USDT}$:
   * Якщо $Price \le 2\text{ USDT} \implies S_{price} = 100$ (максимальний бал).
   * Якщо $Price > 2\text{ USDT} \implies S_{price} = \min\left(100, \frac{2}{Price} \times 100\right)$ (чим вища вартість, тим нижчий підсумковий бал).

#### 3.3. Підсумкова формула інтегрального рейтингу

$$Score = (w_1 \cdot \tilde{S}_{vol}) + (w_2 \cdot \tilde{S}_{vola}) + (w_3 \cdot \tilde{S}_{trades}) + (w_4 \cdot \tilde{S}_{depth}) + (w_5 \cdot \tilde{S}_{price})$$

*(де $w_1 \dots w_5$ — коефіцієнти ваги параметрів, а $\tilde{S}$ — нормалізовані значення за шкалою 0–100).*

### 4. Архітектура локальної бази даних (SQLite)

Локальна база `anomalies.db` призначена для накопичення історії аномалій без навантаження на основний потік обробки.

```sql
CREATE TABLE IF NOT EXISTS anomaly_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    symbol TEXT NOT NULL,
    price REAL NOT NULL,
    volume_surge_pct REAL NOT NULL,
    volatility_pct REAL NOT NULL,
    trades_count INTEGER NOT NULL,
    orderbook_density REAL NOT NULL,
    calculated_score REAL NOT NULL,
    detected_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_anomaly_symbol ON anomaly_logs(symbol);
CREATE INDEX IF NOT EXISTS idx_anomaly_score ON anomaly_logs(calculated_score DESC);
CREATE INDEX IF NOT EXISTS idx_anomaly_time ON anomaly_logs(detected_at DESC);
```

### 5. Специфікація інтерфейсу (UI/UX)

Інтерфейс спроєктовано у форматі сучасного преміального крипто-скринера у стилі TradingView / Binance Pro в темній темі (Dark Mode).

#### 5.1. Візуальна палітра та стилістика (Design System)

* **Головний фон (Background):** Глибокий темний Dark Slate (`#0B0E14` та `#131722`).
* **Контейнери та картки (Cards/Panels):** `#1E2329` із тонкими напівпрозорими кордонами `#2B313A`.
* **Акцентні кольори:**
  * **Зелений (Bids / Покупки / Приріст):** Неоновий смарагдовий `#0ECB81` / `#00C076`.
  * **Червоний (Asks / Продажі / Падіння):** Рубіновий `#F6465D` / `#FF3B30`.
  * **Золотий/Янтарний (Сплески та High Score):** Неоновий жовтий `#FCD535` / `#FFB800`.
  * **Бейдж ціни $\le 2\text{ USDT}$:** Яскравий зелений бейдж із неоновим світінням (`bg-emerald-500/20 text-emerald-400 border border-emerald-500/40`).

#### 5.3. Деталізація функціональних блоків

1. **Header & Control Bar (Шапка управління):**
   * **Індикатор підключення:** Пульсуюча зелена/червона точка `● LIVE BINANCE STREAM`.
   * **Метрики системи:** Відновлювані лічильники кількості активних USDT-пар, кількості записів у `anomalies.db` та статусу з'єднання WebSocket.
   * **Панель фільтрації:** Пошук за назвою (наприклад, `PEPE`, `SOL`), перемикачі швидкого фільтру (`Всі`, `Ціна < $2`, `Score > 80`).

2. **Main Live Leaderboard (Головна таблиця рейтингу):**
   * **Сортування у реальному часі:** Автоматичне впорядкування за спаданням `SCORE` (з можливістю кліку на будь-яку колонку для пересортування).
   * **Бейдж приорітету ціни $\le 2\text{ USDT}$:** Монети ціною до $2\text{ USDT}$ підсвічуються спеціальним зеленим тегом `<$2`, що візуально виділяє їх у списку.
   * **Візуалізатор об'єму (Vol Surge Bar):** Показник приросту об'єму відображається у вигляді прогрес-бару із відсотком (наприклад, `+480.5%`).
   * **Динамічні індикатори оновлення (Flash Animations):** При зміні підсумкового Score рядок плавно підсвічується зеленим/жовтим спалахом.
   * **Кнопка дій (`[INSPECT]`):** Клік на монету або кнопку відкриває нижню панель деталізації (Asset Inspector).

3. **Asset Inspector (Інспектор обраного активу):**
   * **Order Book Depth (Стакан лімітних заявок):** Подвійна візуальна гістограма глибини (Bids зеленим ліворуч, Asks червоним праворуч) із розрахунком сумарного об'єму у $ \pm 1\% $ від ціни.
   * **Live Trade Tape (Стрічка угод у реальному часі):** Жива вертикальна таблиця останніх 20 угод вибраної монети (Час, Ціна, Кількість, BUY/SELL) із зеленою/червоною підсвіткою.
   * **SQLite Anomaly History (Історія аномалій з БД):** Хронологічний список останніх 10 сплесків цієї монети, витягнутий з локальної бази SQLite `anomalies.db`.

### 7. Поетапний план реалізації

* **Етап 1: Мережевий рівень та фільтрація:** Реалізація модуля підключення до Combined Streams біржі Binance, підтримання пулу активних з'єднань, розрахунок ковзних вікон об'єму та волатильності.
* **Етап 2: База даних та персистентність:** Створення схеми таблиць у SQLite, налаштування неблокуючого асинхронного запису аномалій у режимі WAL при спрацьовуванні порогових фільтрів ($\Delta V \ge 150\%$, $\sigma \ge 10\%$).
* **Етап 3: Двигун ранжування (Scoring Engine):** Реалізація алгоритму розрахунку підсумкового балу за 5 параметрами з пріоритизацією монет до $2\text{ USDT}$ та нормалізацією значень.
* **Етап 4: Локальний шлюз (Server & WS Gateway):** Розробка легкого бекенду для трансляції актуального рейтингу та обробки запитів на вибірку історії з бази даних.
* **Етап 5: Побудова інтерфейсу (Frontend Screener):** Верстка трьохзонного Dark Mode інтерфейсу у стилі TradingView (Header, Main Leaderboard із бейджами та прогрес-барами, Asset Inspector з живим стаканом, стрічкою угод та історією з SQLite).
